ImageStorage Connector 0.4.4 / Windows

【以前の版から更新するとき】
自動読み込み・書き出しには、拡張機能0.4.4と本体0.15.53以降を使用してください。
書き出し項目は、Pinterestのボードを開いているときだけ表示されます。
書き出し操作から自動収集を始め、追加読み込みが終わってからファイルを作成します。
古いImageStorageを終了し、新しいポータブル版をフォルダーごと展開して起動してください。
接続済みの環境では、通常は連携セットアップのやり直しは不要です。
読み込み済みの chromium フォルダーを更新したあと、Chrome / Edgeの拡張機能管理画面で
ImageStorage Connectorの更新（丸い矢印）を押してください。
Zen / Firefoxは新しい zen/manifest.json を一時的なアドオンとして読み込んでください。
その後、画像を開いているWebページも再読み込みしてください。
表示位置の取得用スクリプトを読み込むため、このページ更新が必要です。

【初回の設定】
1. ImageStorage 0.15.51以降をインストールするか、ポータブル版をフォルダーごと展開してください。
   古いImageStorageが起動している場合は、いったん終了してください。
   0.15.55以降のインストール版では、完了前にChrome・Zenを選ぶと導入手順が表示されます。
2. browser-connector フォルダー内の SetupConnector.exe を開き、「連携を設定」を押してください。
   このWindowsユーザーだけに設定されます。管理者権限は不要です。
3. ImageStorageの新版を起動してください。

【Chrome / Edge】
Chrome: chrome://extensions/
Edge: edge://extensions/
上記の管理画面で「デベロッパーモード」を有効にし、
「パッケージ化されていない拡張機能を読み込む」から chromium フォルダーを選んでください。
ChromeとEdgeにはそれぞれ読み込んでください。同じフォルダーを選択できます。

【Zen / Firefox 140以降】
ブラウザーで about:debugging#/runtime/this-firefox を開き、
「一時的なアドオンを読み込む」から zen フォルダーの manifest.json を選んでください。
この開発版は、Zenを再起動すると解除されます。
通常のアドオンとして継続利用するには、Mozillaの署名を受けたXPIが必要です。
同梱のZen用ファイルは未署名です。ブラウザーの署名検証を無効にする必要はありません。

【画像を送る】
画像または画像のあるカードを右クリック → ImageStorageに保存… → 横に展開される保存先リストを選択
右クリックメニューの「ImageStorageに保存…」の横に、そのままリスト項目が並びます。
リストを切り替えずに、指定したリストへ画像が追加されます。
リストの並び順はImageStorage側と同じです。現在開いているリストには目印が付きます。
通常の保存では、ページ内の一覧や別ウィンドウを開きません。
Pinterestの保存済みボードや関連画像など、画像の上にリンクが重なったカードにも対応します。
保存先を選んだ時に、そのリンクの画像をページ内で確認して保存します。
画像が見つからないリンクでは保存しません。隣の画像やページのメイン画像への置き換えは行いません。

100リストを超える場合は「リスト 101〜200」のような続きのメニューから選べます。

【すでに保存されている画像】
画像にカーソルを合わせると、接続中の本体に保存状況を問い合わせます。
その画像が入っているリストにはチェックと「保存済み」が付きます。
保存済みのリストをもう一度選ぶと、チェックが外れ、そのリストから画像を削除します。
同じ画像がそのリストに複数ある場合は、該当する画像をまとめて外します。
他のリストの画像や元画像のファイル、Pinterest側の保存状態は変更しません。
解除後にもう一度リストを選ぶと保存し直せます。
本体を起動中であれば「元に戻す」で解除前の配置ごと復元できます。
ファイルへの書き込み完了後に解除完了を表示します。
失敗した場合は本体の保存状況に合わせてチェックを戻します。
結果を確認できない場合は再送せず、本体で保存先を確認してください。
以前保存した画像も、画像URLまたはPinterestのピンURLが残っていれば判定します。
Pinterestのサムネイルと高解像度版は、同じ画像として扱います。
PCから追加した画像など、元URLが残っていないものは判定できません。
確認だけで本体は起動しません。本体が閉じている場合は接続してから確認してください。
古い本体でも保存操作は使えますが、保存解除は本体0.15.47以降に対応しています。

【新しいリストに保存する】
画像を右クリック → ImageStorageに保存… → 新規リストを作成…
右クリックしたカーソル位置に出る小さな入力欄で名前を入力し、「作成して保存」を押してください。
パネル上部の「新規リストを作成」を掴んでドラッグすると、好きな位置へ移動できます。
ページをスクロールしても移動先に留まり、画面からはみ出さない範囲で動かせます。
入力欄を開くだけでは、ImageStorage本体を起動しません。
本体を閉じていても名前を入力すると保存ボタンが有効になり、
「作成して保存」を押した時だけ、画面を出さずに本体を起動して保存します。
ファイルへの書き込みが完了してから、保存完了を表示します。
保存後は本体が裏で待機します。ImageStorage.exeを通常どおり開くと、
保存したリストを同じ本体の画面で確認できます。
画面の端では、入力画面が見切れない範囲に位置を調整します。
カーソル位置を取得できないページでは、画像に重なる位置に表示します。
選んだ画像の取得が成功すると、新しいリストを末尾に追加し、画像をその中に保存します。
ImageStorageで現在開いているリストは切り替えません。
作成を押す前に、メニュー外のクリック、Escキー、右上の×で閉じると何も作成しません。
画像の取得に失敗した場合も、空のリストは残りません。
作成開始後に閉じた場合は、処理が続くためImageStorage側で結果を確認してください。
ページ内への表示を許可しないページでは、ツールバーの拡張機能ボタンから名前を入力できます。
送信結果を確認できないときは、重複防止のため再作成を止めます。ImageStorageで結果を確認してください。

【複数の画像をまとめて保存する】
画像を右クリック → ImageStorageに保存… → このページの画像をまとめて保存…
または、ブラウザー上部の拡張機能ボタン → このページの画像をまとめて保存… を選びます。
ページ内の一覧で、保存する画像にチェックを付け、保存先リストを選んで「選んだ○枚を保存」を押します。
「すべて選択」「選択を解除」も使えます。保存先のリストを開く必要はありません。
一覧を開くだけでは保存しません。本体に接続できない場合は「起動・再接続」を押してください。
読み込み済みの画像が対象です。小さなアイコン、非表示の画像、未読み込みの画像は除きます。
ページを手でスクロールして画像を読み込んだ後、「画像を更新」で一覧に追加できます。
同じ画像のサムネイルはまとめて扱い、一覧は最大200枚です。
パネル上部を掴んで移動できるので、横に避けて元のページをスクロールできます。
保存は1枚ずつ順に行い、成功・保存済み・失敗・結果の確認が必要な画像を個別に表示します。
元データの取り込みとPinterestの高解像度取り込みは、通常の保存と同じです。
保存済みの画像は重複追加しません。現在開いているImageStorageのリストも切り替えません。
「停止」または×で閉じると、処理中の1枚が終わった後、残りの送信を止めます。
パネルを開いたまま停止すれば、未送信の画像を選んで再開できます。
通信が切れて結果を確認できない場合は、残りの処理を止めます。
その画像は自動で再送しません。重複を避けるため、ImageStorage本体で保存先を確認してください。
保存を開始した後で別の保存先に送る場合は、一括保存を開き直してください。
本体のプロジェクトを切り替えた場合や、元のタブを閉じたり別ページへ移動した場合は処理を停止します。
一括保存パネルは読み込み済みの画像が対象です。ボード全体の読み込みには、下記のボード書き出しパネルを使用してください。

リストの作成・改名は、通常は接続中に自動反映されます。
表示が古いときは拡張機能のボタンから「起動・再接続」を押してください。
ポータブル版を移動した場合は、移動先のImageStorageを一度起動してください。
接続できない場合は、そのフォルダーの SetupConnector.exe から連携を設定し直してください。

【画像と通信】
通常のHTTP/HTTPSページでは、右クリック位置と対象を記録する小さなスクリプトが動きます。
カーソルを合わせた画像のURLと出典URLを、保存済み判定のためPC内のImageStorageに渡します。
この照合で画像をダウンロードしたり、外部サーバーに情報を送信したりはしません。
右クリックの座標と対象要素への参照はページ内で一時的に保持します。
リンク上で保存操作をした場合は、そのリンクに対応する表示中の画像URLを読み取ります。
フレーム内の画像では、親フレームへ座標だけを渡して表示位置を合わせます。
保存操作では、選んだ画像・画像URL・出典ページと保存先を、PC内のImageStorageへ送ります。
パスワードやCookieを取り出す機能、閲覧履歴の収集、画像を中継サーバーへアップロードする処理はありません。
画像を取得するため、元の画像配信サイトとは通常の通信を行います。
通常の画像は元データを取り込み、Pinterest画像は既存の高解像度取り込み処理を利用します。
ブラウザー内だけの画像やログインが必要な画像では、元のタブを開いたまま送信してください。
ブラウザー経由で取得する画像は8MBまでです。通常のURL取り込みには既存アプリの制限が適用されます。
サイト側の制限により取得できない画像もあります。
送信結果を確認できないエラーでは、ImageStorageの保存先を先に確認してください。自動で再送信はしません。

【連携の解除】
SetupConnector.exe の「連携を解除」で、ブラウザーとアプリの接続設定を解除できます。
画像や保存リストは削除されません。拡張機能はブラウザーの管理画面から別途削除してください。

Pinterestの保存済みボードのうち、現在のページに読み込み済みの画像は一括保存できます。
ボード書き出しパネルでは、操作したときだけ先頭から末尾まで自動スクロールできます。


【Pinterestのボードをファイルに書き出す】
1. Chrome・Edge・Zen・Firefoxで、書き出したいPinterestのボードを開きます。
2. 拡張機能のボタン → Pinterestボードを書き出す… を選びます。
   画像の右クリック → ImageStorageに保存… からも開けます。
3. 「全体を収集して書き出す」を押します。先頭へ戻り、追加読み込みを待ちながら末尾まで進みます。
   読み込み途中の画像や、スクロールで画面から消えた画像の情報も保持します。
   ページの手動操作や「全体収集を停止」で自動スクロールを止められます。
4. 収集が終わると、ボード名.imagestorage-board.json を保存します。
   表示件数に対して不足がある場合は、自動書き出しを止めて件数を表示します。
5. 先に収集枚数や画像を確認したい場合は「ボード全体を収集」を使います。
   「画像を確認」で不要な画像を除外できます。
   一部だけでよい場合は「収集済みのみ」を押します。全件収集を省略する操作です。

ファイルにはボード名・ボードURL・画像URL・ピンURL・画像の説明が入ります。
画像本体は含みません。書き出しにはImageStorage本体の起動も不要です。
Pinterestのデータ出力メールを待たず、有料APIや専用サーバーも使用しません。
対象はボードの画像一覧に読み込まれたピン、最大5,000件です。35件の制限はありません。
表示件数を取得できる場合は照合し、不足があれば先頭からゆっくり再確認します。
それでも一致しない場合は、不足を表示します。セクション内や未表示のピンがないか確認してください。
総件数を取得できない場合は、末尾まで進んでも全件収集完了とは表示しません。
手動でスクロールする必要はありません。通常は全体収集が終わるまでファイルを作成しません。
高さ0の仮想画像一覧でも、実際のスクロール領域の末尾まで進みます。
画像一覧の外に表示される追加読み込みの待機表示も確認します。
PinterestのAPIを呼び出す処理や、セクションを自動で開いて巡回する処理はありません。
画像一覧を検出できない場合はエラーを表示し、おすすめ欄だけを書き出しません。
別ボードへ移動すると収集を停止します。書き出し画面を開き直してください。

【ボードファイルをImageStorageへ読み込む】
1. ImageStorage左下の＋ → ボードファイルを読み込む を選びます。
   設定 → プロジェクトとヘルプ からも選べます。
2. 書き出した .imagestorage-board.json を選びます。
3. リスト名と画像枚数を確認して「取り込む」を押します。
4. 画像を1枚ずつ取得し、新しい保存リストにまとめて配置します。

同じピンの重複はまとめます。同じ画像を使う別のピンは、それぞれ取り込みます。
共有する同一画像URLの取得は1回にまとめます。既存の保存リストの配置は変更しません。
今回のファイル形式v2は本体0.15.51以降で読み込めます。以前のv1ファイルも読み込めます。
Pinterestの高解像度取り込みは、通常の保存と同じ処理を使います。
失敗した画像だけを再試行するか、取得できた画像でリストを作成できます。
途中で中止した場合はリストを作成しません。
元のピンや画像が削除・非公開になっている場合などは取得できないことがあります。
対応形式は本拡張機能のボードJSON、最大8MB・5,000枚です。
